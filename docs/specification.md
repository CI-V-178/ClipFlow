# 要件定義書 (Specification)

## 1. システム概要
本システム「ClipFlow」は、AIを利用して動画制作（配信切り抜き、ショート動画、オリジナル動画）を支援するローカルファースト型のデスクトップアプリケーションである。
最終的な編集や意思決定は人間が行うことを前提とし、作業の効率化と高度な提案（設計データの作成）を行う「制作補助ツール」として機能する。

## 2. システムアーキテクチャ・技術スタック
* **プラットフォーム**: Windows (実行環境), macOS (開発環境)
* **アプリケーション形態**: デスクトップアプリケーション
* **UI/フロントエンド**: Web技術 (HTML / CSS / JavaScript)
* **バックエンド・コンテナ**: Electron
* **データベース**: SQLite
* **外部連携**: ffmpeg (メディア処理), 各種AIプロバイダー (Claude / Gemini / OpenAI)
* **クラウドリソース (GCP)**:
  * プロジェクト名: `ClipFlowStudio`
  * 管理アカウント: `carrotinaba@gmail.com`
* **アーキテクチャ方針**:
  * プレゼンテーション層、アプリケーション層、インフラ層などの層分離構造を採用。
  * OS依存処理、Electron依存処理、ffmpeg呼び出し、AIプロバイダー呼び出しをそれぞれインターフェースで抽象化し、プラットフォームやツールの変更に強い設計とする。

## 3. 機能要件

### 3.1 プロジェクト管理機能
* **プロジェクト作成**: 動画ごとに1つのプロジェクトを作成し、一意なIDで管理する。
* **状態管理**: プロジェクトの進行状態（未処理、解析中、解析完了など）を保持・更新する。
* **アセット管理**: プロジェクトに紐づくAI生成物、字幕データ、編集設計データをプロジェクト単位で整理して保存する。

### 3.2 動画管理機能
* **ローカルファイル登録**: ユーザーのローカル環境にある動画ファイルをプロジェクトに紐付ける。
* **メタデータ管理**: 動画ファイルそのものはDBに保存せず、ファイルパスとメタデータ（元動画URLなど）のみをSQLiteに保存する。
* **ファイル追跡**:
  * ファイルパスの変更を検知した際の再スキャン機能。
  * 元ファイルの消失（削除・移動）を検知し、アプリケーション上で認識・警告できる機能。

### 3.3 字幕生成・編集機能
* **自動字幕生成**: Whisper等の音声認識AIモデルを利用し、動画から字幕データを自動生成する。字幕は「編集設計データ」の一部として扱う。
* **データ構造**: 発話者、テキスト、フォントスタイル（種類、サイズ、色、縁取り）、開始・終了タイムスタンプをJSON形式で保持する。
* **手動編集機能**: 生成された字幕内容を人間が手動で確認・修正し、修正版として保存・上書きできる機能を提供する。

### 3.4 AI解析・提案機能
* **機能範囲**: AIは字幕生成と会話解析による「提案」のみを行い、動画の自動カット等の「確定作業」は行わない。
* **見どころ抽出**:
  * 動画内の盛り上がり候補箇所や、ショート動画に向いている区間を抽出する。
  * 抽出した理由（なぜその区間を切り抜き候補としたか）をテキストで出力する。
* **データ出力**: 解析結果はすべて「編集設計情報」として出力される。

### 3.5 AIメタデータ生成機能
* **テキスト自動生成**:
  * 動画タイトル案
  * 動画の概要欄テキスト
  * 関連タグの提案
  * ショート動画用の導入文（フック）
* **生成履歴管理**: 生成された結果、使用したプロンプト、使用したAIモデル名を紐付けてDBに保存する。

### 3.6 編集設計データ出力（編集支援）機能
* **非依存データ出力**: 特定の動画編集ソフトに依存しない汎用的な「編集用設計データ」を出力する。直接編集ソフトのプロジェクトファイルを操作することはしない。
* **将来拡張の準備**:
  * 将来的に Davinci Resolve (スクリプト連携等)、AviUtl、Remotion を用いたテンプレ動画生成などに変換可能な構造を事前に考慮しておく。

### 3.7 AIプロバイダー管理機能
* **マルチプロバイダー対応**: Claude, Gemini, OpenAI の各APIを利用可能とする。
* **プロバイダー切り替え**: ユーザーが使用するAIプロバイダーを任意に切り替えられる機能。
* **抽象化**: API仕様の違いを吸収する層を設け、プロバイダーへの依存を分離する。

## 4. 非機能要件

### 4.1 パフォーマンス・操作性
* **非同期処理**: AI APIとの通信や動画解析・字幕生成などの重い処理は完全に非同期化する。
* **進捗表示**: 長時間の処理を許容し、現在の処理状態をユーザーへ適切に表示する。
* **不要な再処理の防止**: 一度解析した同一動画の解析結果や生成物をキャッシュし、再解析を回避する仕組みを設ける。

### 4.2 データ要件
* **文字コード**: 全てのテキストデータおよび文字コードはUTF-8を標準とする。
* **ローカルファースト**: 動画データやプロジェクト情報はローカル環境でセキュアに保持する。

### 4.3 拡張性・将来構想
* **ネットワークストレージ対応**: 将来的なNAS（Network Attached Storage）環境への移行を考慮したパス管理設計。
* **Web/クラウド展開**: 将来的なWeb UI化やクラウド同期機能の追加を阻害しない分離構造を心掛ける。

## 5. 追記・制約事項
* 本アプリケーションにおけるAIはあくまで「制作補助」の役割を担い、最終判断および編集の確定は必ず人間が行う。
* 現時点では、動画の完全な「編集自動化」や、YouTube等への「自動投稿」機能は対象外とする。
* 動画編集ソフトとの直接的な連携機能は将来的対応として位置づける。
